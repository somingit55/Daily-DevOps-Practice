AWS Auto Scaling — Complete Interview Notes

These notes cover the definition, purpose, use cases, advantages, disadvantages, and important Auto Scaling concepts in simple English for AWS interviews.

1. What is AWS Auto Scaling?
Interview definition:

AWS Auto Scaling is an AWS service feature that automatically adjusts the number of EC2 instances in an Auto Scaling Group (ASG) based on application demand, scaling policies, and configured capacity limits.

It helps maintain application availability and performance while optimizing infrastructure costs.

Example: If an application normally runs on 2 EC2 instances but traffic increases, Auto Scaling can launch a third instance. 
When demand decreases, it can reduce the number of instances, subject to the configured minimum and scaling policies.

2. Purpose of Auto Scaling
The main purposes of Auto Scaling are:
- High availability: Maintain the required number of instances and replace unhealthy instances when configured to do so.
- Scalability: Increase or decrease compute capacity according to demand.
- Cost optimization: Reduce unnecessary instances when demand is lower.
- Performance: Help an application handle changing workloads.
- Automation: Reduce manual work involved in managing EC2 instance capacity.

4. Minimum, Desired, and Maximum capacity
These are three of the most important Auto Scaling concepts for interviews.

Minimum Capacity

The minimum number of instances that the Auto Scaling Group should maintain under normal scaling operations.

Example: Minimum = 2 means the group normally should not scale below 2 instances.




Desired Capacity

The target number of instances that the Auto Scaling Group attempts to maintain. Scaling policies can change the desired capacity.

Example: Desired = 2 means the group aims to run 2 instances.




Maximum Capacity

The maximum number of instances that the Auto Scaling Group is allowed to maintain.

Example: Maximum = 3 means the group cannot scale beyond 3 instances.



Example from your practical

Your ASG configuration:
- Minimum = 2
- Desired = 2
- Maximum = 3
This means the ASG aims to maintain 2 instances and can scale up to 3, but cannot normally scale below 2. If desired capacity increases to 3, the ASG attempts to launch a third instance.
5. Important Auto Scaling concepts
A. Auto Scaling Group (ASG)
Definition: An Auto Scaling Group is a logical group of EC2 instances that AWS manages together to maintain desired capacity and perform scaling operations.

Purpose: To manage the number and lifecycle of EC2 instances automatically.
B. Launch Template
Definition: A Launch Template defines the configuration AWS uses to launch EC2 instances.

It can include:
- AMI (Amazon Machine Image)
- Instance type, such as t3.micro
- Key pair
- Security groups
- Storage configuration
- User Data scripts
Example: In your practical, the Launch Template specifies Ubuntu, t3.micro, a security group, and User Data to install Nginx.
C. Scaling Policy
Definition: A scaling policy determines when and how an Auto Scaling Group changes its desired capacity.

Common types include:
- Target tracking scaling: Adjusts capacity to maintain a metric near a target value.
- Step scaling: Adjusts capacity by defined amounts based on alarm thresholds.
- Simple scaling: Performs a scaling adjustment in response to a CloudWatch alarm, with cooldown behavior.
- Scheduled scaling: Changes capacity at predefined times.
D. Target Tracking Scaling Policy
Definition: Target tracking automatically adjusts capacity to keep a selected metric near a configured target value.

Example from your practical: Your policy targets average CPU utilization of 50%.

Important: A 50% target does not mean an instance launches immediately whenever CPU crosses 50%. AWS evaluates metrics and scaling behavior to determine the required adjustment.
E. Scale-out
Definition: Scale-out means increasing the number of EC2 instances to handle increased demand.

Example: ASG capacity increases from 2 instances to 3.
F. Scale-in
Definition: Scale-in means decreasing the number of EC2 instances when less capacity is needed.

Example: ASG capacity decreases from 3 instances to 2, while respecting the minimum capacity and scaling policy.
G. Amazon CloudWatch
Definition: Amazon CloudWatch monitors AWS resources and collects metrics, logs, and alarms.

Role in Auto Scaling: Scaling policies can use CloudWatch metrics and alarms to determine when capacity should change.
H. Health Checks
Definition: Health checks help determine whether an instance is healthy or unhealthy.

Auto Scaling can use EC2 health checks and, when configured, Elastic Load Balancing health checks to identify unhealthy instances and replace them.
I. Desired Capacity
Desired capacity is worth remembering separately because interviewers frequently ask about it.

It is the target number of instances the ASG tries to maintain. It can change because of scaling policies, scheduled actions, or manual updates.
J. Instance Warmup
Definition: Instance warmup is a period that allows a newly launched instance time to initialize before its metrics are fully considered for certain scaling decisions.

Example: Your policy uses a 300-second warmup period.
K. Termination Policy
Definition: A termination policy helps determine which instance the ASG selects for termination when scaling in.

The exact instance selected depends on the termination policy and other applicable rules.
L. User Data
Definition: User Data is a script or configuration supplied when launching an EC2 instance, commonly used to perform initial setup tasks.

Example from your practical:
#!/bin/bash
apt-get update -y
apt-get install nginx -y
systemctl enable --now nginx
echo '<h1>Hello from Auto Scaling Server</h1>' > /var/www/html/index.html


This script installs Nginx and creates a basic web page when it executes successfully. It does not automatically copy all files from your existing EC2 instances.

7. Advantages of Auto Scaling
1. Automatic capacity management: Reduces manual instance management.
2. Improved availability: Can replace unhealthy instances and maintain configured capacity.
3. Cost efficiency: Can reduce excess capacity during lower demand.
4. Elasticity: Responds to changing workloads.
5. Integration: Works with EC2, CloudWatch, Elastic Load Balancing, and other AWS services.
6. Consistent setup: Launch Templates help create instances with a standard configuration.
8. Disadvantages and limitations
1. Configuration complexity: Incorrect scaling policies can cause undesirable scaling behavior.
2. Startup delay: New instances take time to launch, install software, and become healthy.
3. Application state: Local files or session data may not automatically transfer to new instances.
4. Cost: Scaling out increases resource usage and can increase costs.
5. Metric limitations: CPU alone may not accurately represent application demand.
6. Dependency failures: A new instance may become unhealthy if User Data, networking, permissions, or application configuration is incorrect.
7. Not a complete disaster-recovery solution: Auto Scaling alone does not protect all data or eliminate every application failure.

10. One-minute interview answer

“AWS Auto Scaling automatically adjusts the number of EC2 instances based on application demand and configured scaling policies. It helps maintain availability, improve performance, and optimize costs.

An Auto Scaling Group manages the instances using a Launch Template. Minimum capacity defines the lower limit, desired capacity is the target number of instances, and maximum capacity defines the upper limit.

Auto Scaling supports scale-out and scale-in operations. It integrates with CloudWatch for metrics and scaling policies, and with an Application Load Balancer to distribute traffic across healthy instances.

In my hands-on practical, I created a Launch Template, configured an Application Load Balancer and Target Group, 
created an Auto Scaling Group with minimum 2, desired 2, and maximum 3 instances, and configured a target-tracking policy with a 50% average CPU utilization target.”
